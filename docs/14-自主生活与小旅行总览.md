# 自主生活与小旅行总览

小旅行属于 Lunar 的自主生活：她偶尔出门，房间暂时空下来，过一会儿带回一件有故事的纪念物。用户不用一直看着设备，也不需要喂养、签到或每天派任务。

本篇是 `docs/` 顶层的专题入口，汇总已有设计。详细需求和实现规则仍以 [M06需求](modules/M06-life-trips/requirements.md) 与 [M06开发](modules/M06-life-trips/development.md) 为准；当前尚未实现代码或实机验证。

## 1. 用户看到的一趟旅行

| 阶段 | 体验 | 已有规则 |
|---|---|---|
| 日常生活 | 她发呆、玩耍、观察或睡觉 | 基础生活状态可离线运行，作息可配置 |
| 出发 | 她出门了，Home进入空房间状态 | 规则决定是否可以出门，故事先生成并通过校验 |
| 外出 | 用户暂时看不到她待在房间里 | 仍可对话和使用工具，旅行不锁住设备 |
| 返程 | 她回来了，好像带回了一件小东西 | 规则控制返程时间，出发后断网也可本地返程 |
| 看纪念物 | 看见物品、一个观察和她的一句话 | 有限视觉模板配合AI生成的含义 |
| 留下回忆 | 之后还能找到这趟故事 | 返程后才生成完成记忆，故事与现实经历分别记录 |

例如，她去了便利店，带回一张湿掉的饮料贴纸，说：“雨比想象中大。”有趣的部分是物件背后的观察与角色表达，而不只是“获得贴纸”的通知。此例是故事示意，不代表实际天气、到访或官方角色台词。

## 2. 哪些由规则决定，哪些交给AI

**程序决定世界规则**：允许去的地点、是否适合出门、外出时间、物件类型、调用次数、冷却和焦点优先级。

**AI在范围内生成内容**：去向、观察、纪念物含义、角色短评。输入使用当前角色预设、允许的背景和有来源的上下文；不能让生成文本直接改规则、时间或数据来源。

既有M06设计采用每日尝试窗口和调用上限，外出时长建议10–30分钟，检查最近5次故事的重复度。数值是待试用的初始设置，详见模块文档。

## 3. 纪念物与角色形象

纪念物采用“有限视觉模板＋动态语义”。例如同一票根模板可以承载不同故事中的电影票或游船票；贴纸、树叶、包装纸等也能成为一次观察的载体。

每个纪念物关联唯一旅行事件，继承“小旅行故事”来源。角色形象和物件视觉由资源包提供，不要求Core在运行时生成新图片。

Lunar是默认角色预设。地点规则、说话方式和视觉资源应能随角色设定替换，业务代码不固定某一种人格。

## 4. 小旅行怎样进入记忆

- **尚未出发**：生成内容只是计划草稿，不能被回答成已经发生的经历。
- **已返程**：保存角色故事与关联纪念物，来源为 `fictional_trip`，世界范围为 `character_world`。
- **用户听她分享**：可以另记实际发生的分享互动，但不能因此写成“两人一起去了便利店”。
- **以后想起**：按相关性、重要性和主动使用限制决定是否提及；旅行也可以成为长期记忆。

自省可以引用旅行故事，但不能将其转化为用户现实事实。参见 [12 分层记忆](12-人格关系与分层记忆系统.md) 与 [13 Ombre Brain适配](13-Ombre-Brain参考与记忆实现方案.md)。

## 5. 不看设备、断网或正在说话时

先准备有效故事再出发，避免因为生成服务断网而一直回不来。返程记录可以先进入Core的待同步队列，恢复网络后上传原事件，重复同步不重复生成回忆。

用户几天没使用，不补生成一堆旅行，也不扣关系或给予惩罚。正在录音、提醒临近等情况下不新出发；返程主动分享遵守统一焦点与主动回忆规则，普通场景动画和主动语音分享分别处理。

离线、重启、角色切换、生成失败等边界的具体行为与测试见M06开发文档。
