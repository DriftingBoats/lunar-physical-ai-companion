# 数据模型：云端主库与有界设备缓存

## 数据归属与保留

| 数据 | 主本 | Core与浏览器 |
|---|---|---|
| 完整记忆/Profile/摘要/索引 | 云数据库 | Core≤100条/128KiB；Profile≤8KiB；浏览器按需分页 |
| 最近上下文 | Core短期，云端可保存受控摘要 | 最近6轮，模型上下文建议≤12KiB且服从token上限 |
| 待上传事件outbox | 云确认前Core保管 | ≤200条/256KiB，不覆盖未确认事件 |
| 提醒 | 云管理记录＋Core执行副本 | 本地创建即生效；网页创建须设备ack |
| 配置 | 云desired＋Core applied | 不混淆待应用与成功 |
| 动画和固定声音 | 资源包、设备SD | 不全加载RAM |
| 原始录音 | 当前任务临时数据 | 结束清理，不上传记忆库 |
| TTS/翻译媒体 | Core有界缓存 | 建议20条/7天，超容量先清媒体 |
| 备份 | 云备份策略＋用户逻辑导出 | 缓存不是备份；PWA退出清私密本地缓存 |

上限取条数与字节中先达到者，单条缓存正文≤2KiB，长记录用摘要与ID。所有数量是建议初值待测。云可扩容，Core不能跟着全库增长。

## 云表

users、companions、devices、character_versions、configurations、provider_profiles、events、memories、profile_facts、recent_context、reminders、assets、sync_changes、deletion_ledger、tasks。

共用id、owner_id、revision、created_at、updated_at、deleted_at。记忆专属source_type、evidence_event_ids、character_preset_id/version、occurred_at、generated_at、context_sources。事件event_id唯一；角色版本preset_id+version唯一且发布不可原地改写。devices存token_hash、companion、last_seen、applied_revision。

PostgreSQL外键、约束、索引和权限一起迁移。行权限加服务端owner/companion检查；管理密钥只服务端。每次事件、记忆、sync change在同一事务提交，再ACK。索引是派生数据，重建不改变来源。

## 来源规则

分层记忆新增字段和状态以 [人格关系与分层记忆系统](12-人格关系与分层记忆系统.md) 为准：retention_tier（temporary/short_term/long_term）、memory_kind、realm、subject_refs、epistemic_status、confidence及依据、lifecycle、expires_at、user_pinned、proactive_policy。保留层级不改变来源；临时记忆过期不删除业务提醒或未确认outbox。

时间扩展 event_time={start,end,precision,timezone,basis,original_expression,resolved_at}、valid_from/to、recorded_at、narrative_time。原occurred_at仅在事件时间精确时填确定值，未知可null；历史记录迁移不得把created_at当发生时间。故事有独立的生成、计划、实际设备返程和叙事时间。

新增表：memory_scores（分项、计算分、理由、模型/规则版本、override）、memory_dependencies（派生记录与证据）、relationship_state（称呼/关系/边界及证据）、character_learning_proposals（待接受的角色学习项）、consolidation_jobs（整理任务）、recall_plans（主动候选）、recall_deliveries（幂等展示回执）。所有表继续带owner/companion权限，关系不存单一好感度。

评分与整理任务使用memory_id+revision+policy_version唯一键，AI输出不直接改核心preset；重要性分数不代表真实性。删除或纠正证据会让相关摘要、关系推断和主动候选失效。用户固定项不因recency衰减删除，独立证据计数不包含系统自己复述。

迁移建议schema v2：旧source_type保持；明确旧长期记录标long_term，其余保留unknown待分类而非猜测短期TTL；realm可由来源确定，subject和时间缺失保持未知并禁用依赖这些字段的主动触发。先迁移读取兼容层、后台回填、校验，再启用自动到期任务；不让迁移立刻批量删除旧正文。

fictional_trip为故事；shared_experience为可证明设备交互；user_reported为用户自述。Profile不得引用fictional_trip。一次翻译不证明在曼谷点餐成功。AI筛选“重要”不改变来源。用户编辑保留原source_type；新增确认以单独关联记录表达。

## 设备存储与容量

NVS保存令牌、小配置、关键提醒与检查点；SD保存媒体、有界缓存和outbox日志。快照含schema、revision、checksum；临时写校验后切换活动指针，避免每帧写Flash。

outbox先落盘才显示暂存；云accepted后清除。满队列暂停自动旅行生成与归档；主动保存提示先联网同步，基本对话不锁死。没有SD时内置配置和提醒继续，缓存缩减并如实显示能力。

## 同步与冲突

云主本有authority_epoch，sync cursor基于提交顺序。恢复连接先删除变更、再事件上传和普通缓存。设备持久化成功再推进cursor；丢ACK允许安全重传。过期cursor保留outbox重新取有限快照，不拉全库。

云是记忆编辑权威，设备只新增允许来源事件。配置desired由PWA编辑，设备验证资源后ack；失败保持旧版本。提醒completed/cancelled为终态，旧snooze不复活。服务端revision裁决，不能只比较不可靠设备时钟。

## 删除、备份与恢复

删除事务写墓碑和最小deletion_ledger，查询立即排除；再清索引、摘要引用、依赖事实和设备缓存。设备离线无法即时清理，PWA显示待同步。恢复旧备份、重建索引、重新生成摘要都应用删除标识。

逻辑导出含schema、来源、版本、配置和删除标识，默认无密钥和原始录音。云自动备份建议30天滚动，具体支持与费用随服务选型确认，恢复必须演练。换Core重新配对；云主库恢复或迁移增加epoch，设备确认后重建有限缓存。缓存不能代替全历史恢复。

验收：1万条数据、删除依赖、满outbox、SD拔出、旧epoch、跨用户权限、同事件重传、旧备份恢复。
