# Core直连AI：模型全部远程运行

当前主架构是 [云端记忆](11-云端记忆服务开发基线.md)＋有限设备缓存＋PWA。本文只定义AI主链路，完整记忆不放Core，不要求手机中转。

| 能力 | 运行地点 | Core的工作 |
|---|---|---|
| STT/Whisper服务 | 服务商服务器 | 录音上传、取文字 |
| LLM/翻译/故事生成 | 服务商服务器 | 组装有限上下文、校验结果 |
| 高质量TTS | 服务商服务器 | 发文字、下载并解码音频 |
| 固定预录台词 | SD/内部资源 | 断网也可播放已有文件 |
| 动画/按键/提醒执行 | Core | 本地规则与驱动 |
| 全历史记忆与检索 | 云记忆服务 | 查询少量结果、有限缓存 |

Core不加载语音或语言模型权重。标称8MB PSRAM用于缓存与运行时资源，不能按电脑思路装模型。[硬件规格](https://docs.m5stack.com/en/core/StackChan_Core)

## 1. Provider选择

先选一组实际可达、支持中泰语言且协议能被设备实现的STT/LLM/TTS服务。适配器需交付官方文档URL、endpoint、认证、模型、请求体、返回格式、大小上限、错误映射与计费信息；选型尚未完成，不虚构URL。

内部函数transcribe/reply/translate/synthesize/weather，统一Result含data、usage（可未知）、request_id、error。不同服务不一定同协议。个人AI key保存在本人设备配置，固件仓库不含密钥；记忆库管理密钥永远不下发。

## 2. 音频管线

建议输入WAV PCM16/16kHz/mono，最长20秒约625KiB；服务不支持时明确转换。TTS返回WAV/PCM或设备已有解码器支持格式，不能把MP3字节直接当PCM。

长按A→STT→记忆查询（最多2秒）→LLM→本地动作持久化→TTS→播放。所有步骤共享45秒等待上限；成功的提醒动作不因TTS失败回滚。超时或取消后旧响应不得播出。

先全部短句完成再返回，性能不达标时优化分句生成/分段播放；不要首次同时引入全双工和流式多协议。说话动画可用音量包络，不假称精确口型。

## 3. 内存与缓存

320×240 RGB565双缓冲约300KiB，录音最大625KiB，另计TLS、JSON解析、音频解码和栈。响应增量读取，有界解析，避免同时缓冲多个TLS大响应。每设备一个用户音频任务，天气和故事让位。

云记忆最多5条/8KiB；Core缓存≤100条/128KiB、Profile≤8KiB、outbox≤200条/256KiB；完整索引在云端。历史增长不增加Core全量扫描。最近上下文建议6轮、总序列化≤12KiB并服从provider token上限。

## 4. 泰文显示门槛

设备直连返回Unicode文字，本地必须正确呈现组合符号、换行和分页。字体有字不等于排版正确。[Shaping概念](https://harfbuzz.github.io/what-is-harfbuzz.html)

M0/M1做字体/渲染专项探针：电脑参考样张→同文本实机→检查字形定位和高低附标→记录heap与速度→固定库或轻量排版实现。尚未验证哪种本地方案满足全部需求，不能假定M5GFX打印UTF-8就通过。动态泰文失败时翻译模块不发布。

可选云端排版只作为明确评审的回退，不是当前暗含的依赖。若启用，须补接口和离线分页图缓存，不得声称纯本地渲染已完成。

## 5. 最小开发验证

显示/八键/录音→正确证书HTTPS小请求→3秒录音STT→固定文本TTS播放→对话串联→并行动画/缓存同步内存测试。没有密钥先用Mock；真实provider接入和音色验收不能由Mock代替。Lunar正式声音依据认可样音另验收。

## 6. 断网

可以Home、作息、已同步提醒、固定声音、缓存回忆；不能新STT/LLM/TTS或完整云检索。用户看到的是可解释的暂不可用，不是假成功。网络恢复同步outbox，不重放已取消对话、不补生成大量旧故事。
