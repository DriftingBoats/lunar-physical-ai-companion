# M02 固件、屏幕与按键｜开发

关联 [需求](requirements.md)。固件负责协调模块，具体业务各自独立。

## 1. 事件驱动结构

主循环持续读取 M5 更新与按键，不做阻塞 HTTP。InputService → EventQueue → Router → 当前页面 / Feature。网络和音频工作线程通过队列报告结果，禁止直接跨线程画屏。每个会话有 session_id，旧 session 的结果直接丢弃。

| 组件 | 职责 |
|---|---|
| InputService | 去抖、按下/松开、长按、方向连发 |
| Router | Home、Menu、Translator、Memory、Settings 页面栈 |
| FocusManager | 当前可接收按键及播放声音的任务 |
| SceneRenderer | 背景、角色、覆盖文字、提示条的分层绘制 |
| AudioService | 录制与播放互斥，退出释放资源 |
| NetworkService | 有界请求队列、超时、取消 |

## 2. 输入算法

建议去抖 20ms、长按 350ms、方向重复起始 500ms 后每 150ms。采用单调计时器计算间隔，不使用会被网络校时修改的时钟。

```text
稳定按下 -> 记录 down_at、captured_page、long_sent=false
仍按下且超过阈值 -> 发 LONG_START，一次；long_sent=true
稳定释放 -> 若 long_sent 发 LONG_END，否则发 CLICK
页面退出 -> 取消该页任务；屏蔽仍按住的键直到释放
```

录音只有在 LONG_START 后开始；显示倾听或短提示音后用户讲话，不偷录短按期间的声音。同时按 A+B 时只接受先获得音频焦点的一键，另一键直到释放忽略。

## 3. 焦点与状态

优先级：设备关闭/升级保护 > 用户当前录音 > 到期提醒 > 当前播放/交互 > 自主动画。提醒到达录音期间先排队，最长等待当前 20 秒录音结束；等待 AI 回复期间可显示提醒并取消旧会话播放。所有被取消的音频 job 即使晚到也不自动响起。

Home 的生活状态与对话状态分离。例如角色睡觉时用户讲话，只覆盖 Listening，结束后由生活规则决定回睡眠或短暂醒着，不能直接把整个状态机重置。

## 4. 布局基线

逻辑画布 320×240；旋转由 HAL 映射。Home 建议顶部 24px 状态区、中部 184px 场景、底部 32px 条件提醒；无提醒时场景可延伸。翻译页自己控制版面。字体和坐标不按概念图缩放推导，必须实机检查。

静态背景缓存，动态角色局部重绘；按需重绘文字。中文固定 UI 字体打包；动态泰文参见 M05。资源缺帧回退 idle，不白屏。渲染返回失败时保持最近有效帧。

## 5. 交付与测试

交付输入状态机、路由、焦点仲裁、五个基础页面及测试事件注入入口。主机测试 349/350/351ms 边界、去抖、同时按键、换页释放；实机测录音+联网时按键延迟、触摸映射、100 次返回无内存增长。

错误页只显示可理解的短文案和重试/返回；request_id、错误码进入诊断日志。不要把串口调试菜单混入日常 Home。
