# M05 中泰翻译｜开发

关联 [需求](requirements.md)。沿用 Core 直连音频管线，内部 mode=translation，固定本次 source_language 与 target_language，不在录音中途切方向。

## 管线

输入校验→指定源语言 STT→直译任务→结构校验→目标语 TTS→文字排版→缓存历史。禁止对翻译内容执行提醒等工具：翻译“七点提醒我”只输出译文，不能创建提醒。

内部结果保存 source_text、text、language、local_audio_path 与分页状态；记录 event_id 和语言方向。会话记忆只保存设备完成翻译这一事实，不能从内容推断实际城市、交易成功或用户出行。

## 泰文显示方案

Unicode 文本与“字体有字”不等于排版正确。泰文组合符号定位需要验证；[HarfBuzz](https://harfbuzz.github.io/what-is-harfbuzz.html) 说明了字符到字形的 shaping。

主方案先做本地排版专项探针：电脑生成参考样张，Core 使用含 Thai 字形且经验证支持组合符号定位的本地渲染方案，对比同一组文本。具体库与内存占用待验证，不假设 M5GFX 直接打印即可正确。保留 Unicode 文本。若本地方案失败，模块不验收；云排版图片只能经明确评审后作为可选回退，不能暗中依赖手机或后端。

默认内容宽 288px、高 152px，周围保留状态与操作区；字体约 24–28px 起测。按实际字形宽度、组合簇和语言换行规则分页，不按字节数或任意 code point 截断。原文也可能为泰文，原文区同样需要正确排版；长原文在详情中分页面显示。

在线翻译失败不能靠显示占位文案假装成功。排版失败但翻译成功时标记显示失败，可播放已有语音；不能用乱码作为正常结果。缓存文字、本地分页信息和声音，LRU 清理成组处理并维护可回放状态。

## 开发步骤

1. 用固定的中泰文本跑通页面，不接麦克风。
2. 校验泰文样张与长句分页，实机检查最高和最低附标。
3. 接共享录音服务，验证 A/B 短长按。
4. 接真实翻译与 TTS，建立 40 句质量样本。
5. 加入历史缓存、播放失败重试、断网与切页取消。

验收包括含数字、语尾、标点、空格很少的长泰文；记录模型与音色版本，后续换服务必须重跑质量集。性能按松键到首段可播放计时，分别记录 STT、翻译、排版与 TTS，先找真实瓶颈再换传输方式。
