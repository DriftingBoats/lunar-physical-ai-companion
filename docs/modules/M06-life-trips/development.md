# M06 自主生活与小旅行｜开发

关联 [需求](requirements.md)。Core 内 LifeEngine 与 TripCoordinator 分开；TripCoordinator 直连外部 LLM 生成文字。

## 1. 本地规则

LifeEngine 输入：有效本地时间、天气新鲜度、用户作息、上次状态时间、当前交互占用；输出 life_state、animation_id、next_check_at。使用固定随机种子可重复测试，不使用每帧概率抽签。

空闲行为建议持续 30–180 秒，睡眠按时间段，用户互动短暂覆盖。跨午夜作息用日期区间计算；无有效时钟时保留安全 idle，不编造昼夜。重启从检查点恢复并按当前时间纠偏，不快进播放数百个状态。

## 2. 旅行状态

```text
eligible -> requesting -> story_ready -> away -> returned -> archived
requesting -> failed/skipped -> idle
```

先拿到通过校验的故事和纪念物，再安排出发，防止出门后因断网永远回不来。出发后本地 return_at 到点必返程，网络只用于同步归档。AI 不得决定 return_at；建议外出 10–30 分钟，由规则引擎取值。

正在录音、距离提醒不足 10 分钟、夜间、未过冷却、天气过期时不新发起旅行。Core 调度器检查资格、预算、角色版本与 rule_version，归档服务再次校验来源和事件结构。请求携带唯一 plan_event_id，重试复用。

## 3. 生成结果结构

```json
{
  "location_id":"corner_shop",
  "observation":"窗边的杯子上有一圈水汽。",
  "souvenir_template":"sticker",
  "souvenir_text":"一张饮料贴纸",
  "comment":"今天的窗边很安静。"
}
```

地点、纪念物是规则枚举；文本建议分别 ≤120、40、60 汉字等价长度，按 Unicode 字符限制并再测版面。Core 加 event_id、fictional_trip、生成时间、叙事时间、角色版本及上下文来源，不能让模型填写 source_type。

校验枚举、类型、长度、明显的用户亲历断言、规则冲突和与最近 5 次故事的重复度。机械检查只能捕获一部分语义问题，来源隔离不依赖语义分类器。重复或失败最多再生成一次；仍失败不产生纪念物，也不写已完成旅行。

## 4. 交互、切换和恢复

Away 时 A 对话可展示角色远程回应的轻量表现，工具继续可用；底层 return_at 不变。角色切换在旅行归档后应用，防止 A 角色出门、B 角色带回纪念物。断电重启发现过了 return_at，直接显示一次返程摘要，不再次生成。

归档事件唯一约束防止重复回忆。云记忆服务不可用时保存本地 outbox；恢复连接后上传原事件，不改变其来源与发生时间。旅行故事绝不触发 Profile 自动提取。

## 5. 测试

用注入时钟检查午夜、长时间离线、提前校时；模拟 AI 枚举非法、长文本、重复、超时、断电；问“我们去过便利店吗”只能说明故事，无现实证据时不承认实际到访。
