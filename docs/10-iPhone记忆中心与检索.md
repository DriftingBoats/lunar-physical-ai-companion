# iPhone 记忆中心与检索：可选历史方案

> **可选历史方案，非当前主线。用户最终选择云端主记忆与 PWA；以下仅在未来明确重启 iPhone 主库路线时使用。**

这是用户最后明确调整的职责：完整记忆由 iPhone 管理和检索，避免历史量增长拖慢 Core。AI 音频仍由 Core 直接访问外部服务。本文与总体架构、数据模型共同构成当前基线。

## 1. 一次带记忆的对话

1. 用户按住 Core 的 A，录音并上传云端 STT。
2. Core 拿到文字，通过已配对 BLE 发送查询，只传文字，不传原始录音。
3. iPhone 在主库按来源、关键词和日期检索，最多返回 5 条且总量 ≤8KiB。
4. Core 把少量结果和当前角色设定加入请求，直连云端 LLM。
5. Core 直连云端 TTS，下载并播放回复。
6. 值得保存的新事件写入 Core outbox，手机可用后事务归档并确认。

向外部模型发送的是选出的少量相关记忆，不是整库上传。用户在 App 能查看和删除记忆；详细资料不得不加筛选全塞进上下文。

## 2. 手机不能及时检索时

建议查询截止为 2 秒，从 BLE 发送成功或发起尝试开始计时；未连接时不先等连接 2 秒再额外等查询 2 秒，整体共享截止。超时就使用有限缓存，绝不无限等待。

| 手机状态 | 当前承诺 |
|---|---|
| 前台、已连接、索引可读 | 完整主库内检索，实际耗时测试 |
| 后台或锁屏 | 尽力检索；按系统行为实测，不保证即时 |
| 被强制退出、权限撤销、超出距离、没电 | 基本对话使用缓存，新事件待同步 |
| 主库迁移、首次解锁前文件不可读 | 返回 NOT_READY 或超时回退，不返回假空库 |

无结果与不能查询不同：前者可以说“没有找到相关记录”，后者对明确历史问题说明“现在只能看到最近的一些记忆”。日常闲聊不必每次插入技术提示，但不能假装检索了全历史。

Apple 的后台模式为特定蓝牙事件提供执行机会，不能保证 App 永久运行；强制退出后的恢复有明确限制。[后台处理](https://developer.apple.com/library/archive/documentation/NetworkingInternetWeb/Conceptual/CoreBluetooth_concepts/CoreBluetoothBackgroundProcessingForIOSApps/PerformingTasksWhileYourAppIsInTheBackground.html)、[恢复规则](https://developer.apple.com/documentation/technotes/tn3115-bluetooth-state-restoration-app-relaunch-rules)

## 3. 有界缓存如何选

缓存最多 100 条/128KiB，先达到者为上限；单条缓存正文建议 ≤2KiB，过长保存摘要与主记录 ID。优先：用户固定事实、用户收藏、最近共同经历、最近成功检索命中。故事有独立来源，不能挤成真实事实。缓存条目带 revision、epoch 和缓存时间。

全库增长只影响手机索引，不影响 Core 的缓存容量和每次查询扫描量。Core 不下载所有记录再自行筛选；手机负责裁剪结果与发缓存快照。查询结果仍必须先过来源和大小校验。

## 4. 数据归档和删除

新事件由 Core 生成唯一 event_id，先持久化再排队。手机收到后验证来源、事务写 events 和 memories，再确认；重复 event_id 返回已接受，不再创建记录。outbox 满时暂停自动故事保存并提示同步，不静默覆盖。

删除在手机立即影响查询；Core 离线仍可能持有旧缓存，因此 App 显示“设备待同步清理”。连接后优先下发删除，再更新其他缓存。用户确需离线 Core 立刻清空，可在设备设置清缓存；不能仅凭手机删除动作声称离线设备已同步。

## 5. 手机实现范围

建议原生 Swift/SwiftUI、CoreBluetooth、SQLite。第一阶段实现记忆列表、来源标签、搜索、编辑、删除、导出和设备状态；之后补 Character、Brain、Plugins、Device。密钥与配对材料使用系统安全存储，记忆库使用系统文件保护；锁屏/重启后何时可读需要测试并回退。

初期先确定性检索，中文使用可验证的分词或子串/倒排方案；泰文需独立样例。语义 embedding 是可选优化：可在手机允许执行时计算或使用外部服务，但不作为首版完成前提，不要求 Core 跑模型。

## 6. 配对与主本

一次只绑定一个记忆主手机；允许换手机，但需导出/导入并在 Core 上确认新的 authority_id/epoch。Bluetooth bonding 不等于完整业务授权，连接后还要校验配对会话的设备身份。协议版本、分块、ACK 和输入上限见接口契约。

App 被卸载或手机损坏时，全历史依靠备份恢复；Core 只存少量副本，无法兜底完整历史。备份导出到用户选择的位置，不默认开启 iCloud 同步。恢复旧备份必须应用当前删除标识。

## 7. 开发顺序

先手机本地插入一万条虚构测试记录，验证搜索和删除；再 BLE 传一条事件并确认；再做重复/断连；然后接对话查询和超时回退；最后测锁屏、强制退出、重启、权限拒绝、系统内存压力。先保证前台准确，后台优化属于有测量结果才承诺的能力。

## 8. 必须记录的性能

手机数据库大小与查询 p50/p95；BLE 8KiB 回复用时；Core 最低可用 heap；Wi-Fi 与 BLE 同时使用时语音延迟；同步一批事件的耗时；锁屏成功率和失败回退耗时。不要因为手机比 Core 强就省略吞吐和并发验证。
