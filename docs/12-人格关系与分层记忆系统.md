# 人格、关系与分层记忆系统 v1.1

实现细节见 [Ombre Brain 参考与记忆实现方案](13-Ombre-Brain参考与记忆实现方案.md)。新增证据片段、自省通道和活跃度；重要性、三层生命周期与主动展示门槛保持本文定义。

本规格落实新增需求：稳定而有自主性的角色人格；长期、短期和临时记忆；真实时间；用户与角色的关系；角色自己的旅行；主动回忆；重要性评分。它是 M03、M04、M06、M08、M10、M14 的共同约束。当前是待实现的设计，数值为初始调试参数，非实测心理学指标。

## 1. 体验目标

她知道自己是谁、喜欢怎样表达、最近在做什么；记得用户主动告诉她的偏好和共同经历；理解“昨天”“上次”“下周”对应的现实时间；合适时自然提起相关回忆。她可以有不同看法、自己的兴趣和旅行节奏，用户几天不出现也不因此被责备。

“独立人格”在产品里落实为一致的身份、表达、偏好和自主行为规则，不把模型生成一句“我喜欢什么”自动当作已经形成的永久人格。不用关系等级或每天互动次数驱动讨好、惩罚或强制照顾。

## 2. 一段记忆有多个独立维度

| 维度 | 字段 | 作用 |
|---|---|---|
| 保留层级 | retention_tier | temporary / short_term / long_term，决定生命周期 |
| 内容类型 | memory_kind | fact / episode / relationship / self_narrative / intention / reflection |
| 来源 | source_type | fictional_trip / shared_experience / user_reported；新增 companion_reflection 只用于角色自省 |
| 世界范围 | realm | real_world / character_world，防止故事当现实 |
| 涉及谁 | subject_refs | user、companion、joint、其他明确实体 ID |
| 认识状态 | epistemic_status | observed / reported / inferred；推断不当确证 |
| 时间 | event_time、valid_from/to、recorded_at | 区分发生、有效、记录的时间 |
| 重要性 | importance_score | 0–100，决定保留与候选优先级，不决定真假 |
| 使用限制 | proactive_policy | allow / ask_first / never |
| 情绪标注 | affect | 可空；效价、唤醒度、主体和依据；不代表确证心理状态 |
| 活跃程度 | activation_score / surface_state | 与重要性分开；低活跃长期事件可 dormant，显式相关查询仍可找到 |

长期/短期不等于真实/虚构。她的一次旅行故事可以长期保留，但始终为 character_world + fictional_trip；“用户说今天累”是 real_world + user_reported，不能因此写成“用户一直身体不好”。

一个摘要若混合现实和故事，拆成分别带引用的条目，不能用一个宽泛 source_type 覆盖所有内容。设备缓存是存储副本，不是第四种心理记忆层；云端长期记忆在 Core 上也只是有界缓存。

## 3. 三层记忆及转移

| 层级 | 例子 | 默认生命周期 | 使用方式 |
|---|---|---|---|
| 临时 temporary | 正在谈哪家店、这次翻译方向、某次等待结果 | 会话关闭后清理；需要跨会话的临时上下文最长24小时 | 当前任务优先，不直接变成人格事实 |
| 短期 short_term | 这几天在准备旅行、近期共同话题 | 最近7天，结束后评估归档或到期 | 接续话题，避免每次重新问 |
| 长期 long_term | 稳定偏好、用户要求记住的事、重要共同经历、被保留的旅行故事 | 无默认自动删除期限；用户可删 | 长期检索与角色连续性 |

生命周期为 active / closed / expired / superseded / deleted，与层级分开。temporary→short_term→long_term 不是所有记录必走的流水线：用户明确要求长期保存可直接进入长期，纯临时操作结果可直接过期。

默认升级规则：

1. 用户明确“记住这件事”：可直接长期保存，标记 user_pinned；保留用户原话来源与时间限制。
2. 重要共同事件 importance≥70：可成为长期 episode 候选；可由异步整理任务按规则确认，不必每次打断对话询问。
3. 稳定偏好：至少两次独立用户表达，或一次明确持久偏好声明，且不存在更新冲突，才形成长期 fact；数字阈值并不能替代判断句意。
4. 仅一次“今天想吃甜的”保持短期，不推断永久喜欢甜食；高重要性的猜测也不能升级为确证事实。
5. 整理任务必须在有效期内完成保留决策；到期未完成则不把过期内容继续塞给模型。审计元数据可保留，已过期正文按策略清理。

进行中提醒、已确认承诺的业务对象及未获云 ACK 的 outbox，不由普通记忆 TTL 删除。临时记忆过期可以停止检索“我们正在说这个”，不能让明天的提醒消失。用户固定的记忆不因长期没提到而被自动删除。

## 4. 真实世界时间

每次对话由 Core 提供经校时的 UTC 当前时间、IANA 时区和 clock_valid；超时使用单调时钟。模型不能自行猜“今天几号”。云端 recorded_at 只代表入库，不替代事件发生时间。

事件时间表示为 start、end、precision（instant/day/month/range/unknown）、timezone、basis（device_clock/user_expression/explicit_date/story_schedule）、original_expression、resolved_at。允许未知和模糊范围，不能为了数据库整齐补出精确日期。

- “昨天吃了面”：根据说这句话时的当地日期解析成昨天的日期范围；两天后同步仍保持原解释，不按入库时间再次解析。
- “去年夏天”：保留模糊范围或原句，缺少地点/年份依据时不编造精确日。
- “下周五见”：将未来计划与已经发生的经历分开，到日期只表示计划到期，不能自动写成“已经见过”。
- “现在不爱喝甜饮了”：旧偏好 valid_to 结束，新事实 valid_from 开始；过去的真实偏好和经历不被抹掉。
- 改时区不移动过去已确定的 UTC 时刻；“今天”由当前时区解释。设备时钟无效或出现未来异常值时标不确定，暂停日期型主动回忆。

故事另外记录 narrative_time；真实设备出发/返程时间用 trip_started_at/trip_returned_at，文本 generated_at 单独存。提前生成的故事在实际返程前为 planned、不可作为已完成经历检索。

## 5. 人格、关系和当下状态分开

| 部分 | 存储 | 谁可以改变 |
|---|---|---|
| 核心人格 | 版本化 character preset：身份、表达、基本偏好、边界 | 用户在 PWA 明确编辑发布 |
| 可积累的角色经验 | self_narrative、角色兴趣候选、共同经历的反思 | AI 可提出，有证据、角色版本和规则校验 |
| 用户与她的关系 | relationship_state 和带证据的 relationship memories | 用户明确设定＋可验证互动摘要；用户可纠正 |
| 当前状态 | 当前任务、作息、短期情绪语气、Away 等 | 本地状态机与本次上下文，默认不永久化 |

关系内容：用户对她的称呼、用户希望怎样被称呼、互动边界、喜欢的互动方式、重要共同经历、仍未解决的话题。relationship_label 只有用户明确指定时保存（例如朋友、陪伴伙伴），缺省不自动推断恋爱或亲属关系。

关系变化以“发生了什么、因此怎样调整互动”记录，不用单一亲密度数字下结论。AI 可以提出“最近多次聊旅行，可能喜欢这个话题”的 inferred 候选，不能将其当作用户确认。几天未使用不扣信任，不自动感到被抛弃；长时间间隔只影响是否需要重新确认近况。

人格漂移控制：普通对话、重要性评分、自动整理都无权修改核心 identity/system_prompt。可学习的兴趣候选单独保存，默认需用户在 PWA 接受才改变持久角色偏好。旅行形成角色世界经验，不生成现实能力证明或用户 Profile 事实。更换预设后旧 self_narrative 留原角色版本，新角色不自动声称亲历；共同历史可带原角色标签检索。

## 6. 重要性评分：可解释、异步、有上限

评分是本项目启发式规则，后续用用户反馈校准，不是模型对人的价值判断。AI 给五个分项及简短理由，每项0–4；服务端验证范围并计算最终分，模型不能绕过计算直接指定最终分。

| 分项 | 权重 | 评价内容 |
|---|---|---|
| identity_relevance | 30% | 是否影响稳定偏好、身份或已确认关系理解 |
| emotional_salience | 25% | 用户明确表达的重要情感意义，不猜测情绪强度 |
| consequence | 20% | 对真实决定、共同任务或承诺的影响 |
| future_usefulness | 15% | 未来可能需要再次用到的程度 |
| distinctiveness | 10% | 是否是可辨识的重要首次或特别经历 |

计算：`importance = round((30*i + 25*e + 20*c + 15*f + 10*d)/4)`。例如分项4、3、2、4、2得到79。明确“请记住”设保留分数下限90并 user_pinned=true；用户手动 override 单独记录操作者、理由与旧分数，不覆盖模型分项。

分段建议：0–29 普通临时信息；30–69 短期优先；70–100 长期候选。**分数不独自决定保留层、真实性、主动提起资格或行动执行。** 一个重要但敏感的记忆可以长期保存同时 proactive_policy=never。

分开保存：importance（长期价值）、epistemic_status/confidence（证据质量）、relevance（本次查询匹配）、recency（新近程度）。confidence 使用 high/medium/low 与依据，不用模型随口的百分比冒充校准概率。

衰减影响检索 recency，不修改原重要性或删除用户固定项。角色自己复述、系统摘要重写、重复投递同一事件不算新的独立证据、不提高分数。用户主动再次谈及才可产生新引用证据；更新有score_version、model_version、scored_at和score_reason。

## 7. 记忆整理与检索

云任务流程：原始允许事件落库→分层候选/实体/时间提取→来源与时态校验→评分→候选升级/去重/摘要→索引更新。任务失败重试幂等，角色和内容版本不匹配时丢弃旧计算结果并重新排队。

模型评分和整理是新增的异步云任务，不加入每次用户查询的2秒路径；服务端需要自己的受控模型配置和预算，不从日志中读取设备密钥。模型不可用时保留待评分状态，短期有效资料仍可检索；规则下限和用户固定仍可立即生效。

查询先权限→删除/生命周期→世界范围/主体→时态有效性→匹配评分。建议排序 `0.60*relevance + 0.25*(importance/100) + 0.15*recency`，三项归一到0–1，relevance 用检索引擎分数归一并通过样例校准。先设最低相关性，不允许不相关但高分的生日挤掉这次在问的车票。

当前事实优先 valid_to 为空或覆盖目标时间的条目；问“以前”允许返回旧版本并说明日期。否定/冲突事实不投票多数决定；最新明确纠正可 supersede，有冲突未解决时提出澄清。

返回最多5条且整个检索 data（含轻量关系摘要和时间说明）≤8KiB。Core 不下载全库。上下文顺序：人格核心→可信当前时间→当前任务→已确认关系与边界→相关事实/经历→单独标注的故事→用户当前话语。

## 8. 主动唤起记忆

两种触发分别计数：

1. 对话中联想：用户提到相关主题，自然引用相关旧事，例如提到下雨时想起有证据的上次淋雨经历。属于当前回复，不算设备主动开口。
2. 空闲时主动发起：纪念日、用户允许的后续关心、旅行返程或合适的共同话题。云端只生成候选，Core 在实际展示时决定是否允许。

初始建议：每天最多2次空闲主动展示，间隔至少4小时；同一记忆7天内不重复主动提起。用户明确要求的定时提醒走Reminder，独立于此额度。关闭主动回忆不关闭已创建提醒。

候选必须有 evidence_ids、trigger、valid_from、expires_at、character_version、memory_revisions、proactive_policy、文本及计划ID。默认候选最长2小时有效；周年类另有当天有效窗口；不能以昨日天气触发今天关心。生成失败不影响用户对话。

展示前门槛：时钟有效、在有效窗内、用户未关闭、非勿扰时段、非睡眠、无录音/播放/提醒焦点、角色版本匹配、频率未超。为避免删除竞态，首版主动发起在展示前在线 validate 候选，核对未删除/未过期/来源与版本，取得短期一次性授权；断网不主动发起，但本地提醒继续。默认只在近期触摸/按键等明确互动后展示轻量提示，用户 A 接受再播放，避免靠不存在的人体感应猜用户在场。

用户 B 跳过不惩罚关系；“别再提这个”将该记忆 proactive_policy=never，并撤销所有引用候选；全局暂停也撤销未展示候选。心理/健康/冲突等敏感内容默认不空闲主动提起，是否适合提及与重要性独立。计划过期不在重连后补播。

认领计划与展示回执用唯一计划ID幂等；计数事务在授权时预留，重启不多算或反复播放。授权已发而设备未展示的短窗处理见接口规则。多设备共享云端额度，避免每台各开口两次。

## 9. PWA 怎样让用户理解

Memory 内提供长期、短期、临时筛选和按日期时间线；每条同时显示“你告诉我的/共同交互/她的旅行故事”、主体、发生时间及是否模糊。重要性显示分数和简短理由，可展开分项、调整保留、固定、删除。

新增“我们之间”：称呼、关系设定、互动边界、重要里程碑、候选推断；用户可纠正，没有等级条。Character 内分核心人格和候选学习项，接受才改变持久预设。主动回忆设置包含开关、时段、频率和不再提及清单。

“发生在何时”“何时保存”“目前是否有效”分开，不用入库时间替代回忆时间。临时记录过期不弹出失去关系之类文案；删除说明仍包括设备缓存待同步状态。

## 10. 必测场景

| ID | 输入/操作 | 预期 |
|---|---|---|
| MEM-01 | “今天想吃甜的” | 短期/临时上下文，不永久改偏好 |
| MEM-02 | “请记住，我不喝咖啡” | 长期reported事实、固定保留，来源不变 |
| MEM-03 | “上个月开始又喝咖啡了” | 新有效区间，旧记录可追溯，模糊日期不补精确日 |
| MEM-04 | 昨天的故事今天上传 | 保留故事时间和真实返程时间，不当今天现实经历 |
| MEM-05 | 昨天生成未来旅行文本 | 未返程不检索为已完成；取消不留虚假亲历 |
| MEM-06 | 过去一周不操作 | 无关系惩罚，无成堆主动补播 |
| MEM-07 | 一个记忆评分99但不相关 | 不挤掉相关查询结果 |
| MEM-08 | AI连续复述同一故事 | 不增加事实置信或独立证据计数 |
| MEM-09 | 提醒明天到期但临时上下文过期 | 提醒仍执行 |
| MEM-10 | 删除证据/说别再提 | 派生摘要、关系候选和主动计划失效 |
| MEM-11 | 云评分服务不可用 | 用户对话不额外等待，评分标pending |
| MEM-12 | 时钟无效/时区变更 | 日期推断不造假，日期型主动回忆暂停/重算 |
| MEM-13 | 在听用户说话时候选到达 | 不抢焦点，过期不播放 |
| MEM-14 | 切换角色后旧候选回来 | 丢弃；旧故事仍归原角色 |
| MEM-15 | 两台设备同时主动认领 | 云额度原子限制，同计划只授权一次 |
| MEM-16 | 高分悲伤记忆 | 保留与主动展示分别受控，不反复主动刺激 |

完成标准不仅是可搜索：用固定情景集验证人格一致、时间正确、关系可纠正、评分可解释、回忆不扰人；记录误记、错误归因和主动打扰情况再调整参数。
