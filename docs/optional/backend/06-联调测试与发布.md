## 4. 性能与体验目标（尚未测得）

- 按键到可见反馈通常 ≤ 100ms；录音开始 ≤ 300ms（不含 350ms 长按判定）。
- Home 动画以 10–15fps 起步；先保证没有明显阻塞，再提高帧率。
- 20 次真实短句对话记录从松键到首段可播放的 p50/p95；初始目标 p50 ≤ 5 秒、p95 ≤ 10 秒。45 秒是终止等待上限，不是可接受日常延迟。
- 待机 2 小时和 100 次任务后检查 heap 趋势、重启计数、音频裂音；有持续泄漏不能发布。
- 记录电池满电至关机实际时长、亮度、音量、联网频率及调用次数；不先承诺一天续航。
- 7 天观察是否愿意主动查看，是否产生照顾负担，第 5 次故事是否重复；不能用技术测试替代产品体验。

## 5. 部署步骤

1. 本机 Mock 与数据库迁移测试通过；锁定所有依赖，记录版本。
2. 选择常在线服务器，安装相同后端；数据库和媒体放持久磁盘，不放临时容器层。
3. 配置域名与有效 TLS 证书；反向代理只转发需要的 API 和网页。生产关闭开发热更新，使用前端静态构建产物。
4. 以独立服务账户启动后端，配置自动重启和数据库备份；首版持久任务 worker 单实例运行，避免重复消费。
5. 配置生产密钥、预算和允许的 provider；浏览器检查身份登录，设备验证证书与正确时间。
6. 用一台测试设备灰度，检查登录、配置 ack、音频任务、重启恢复，最后才发布给日常设备。

不要把 `uvicorn --reload` 或 Vite dev server 当成正式部署。精确部署命令应在代码和服务器选择完成后补充，当前不伪造一个可直接发布的仓库。

## 6. 发布门槛

- 所有确认需求有对应模块与测试；未通过项不能标“完成”。
- 编译、数据库迁移、契约测试、关键人工流程通过；没有未解决的崩溃、数据丢失或身份隔离问题。
- 一次 OTA 失败回滚、一次备份恢复、一次离线删除同步演练完成。
- 固件清单含 hardware_id、version、协议范围、资源版本、hash、签名和恢复指引。
- 发布记录明确哪些仅 Wi-Fi 支持、哪些语音服务已验证、哪些仍是占位素材。

## 7. 日常排错顺序

设备显示离线：先看 Wi-Fi 与系统时间，再看后端 `/healthz`，最后看 provider 状态。能显示文字但无声音：检查 TTS job warning、媒体下载、音量、扬声器示例。设置没变：比较 desired_revision 和 applied_revision。记忆错误：查看来源与 evidence IDs，再修检索规则，不能只换提示词。

日志记录 request_id、job_id、阶段耗时、错误码、内存摘要；默认不记完整私密内容。费用按 provider 用量与单价配置计算，缺少用量时标为估算。设置每日预算，超出后只停止新付费请求，本地生活和已有提醒继续运行。
