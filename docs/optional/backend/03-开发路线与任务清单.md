# 开发路线与任务清单

> 可选历史方案，非当前主线。请以 docs/README.md 和当前总架构为准；这里保留早期全功能后端设计，未实现。

这是一份按依赖排序的施工单。下面所有勾选框初始未完成，阶段编号 M0–M8 与模块编号 M01–M12 是两套编号。

## 阶段表

| 阶段 | 交付物 | 前置条件 | 通过标准 |
|---|---|---|---|
| M0 硬件打通 | 测试固件、版本表、测试日志 | 硬件到手 | 屏幕、八键、录音播放、Wi-Fi、供电逐项有记录 |
| M1 离线会生活 | Home、生活状态、占位角色、菜单 | M0 | 断网运行 2 小时，按键无明显漏失，重启恢复状态 |
| M2 三端 Mock 闭环 | 后端、网页、设备任务 API | M1 | 不付费调用也能走完录音→模拟回复→配置同步 |
| M3 能交流 | 真实 STT/LLM/TTS 适配 | M2、服务配置 | 20 轮对话通过并记录耗时、失败、费用 |
| M4 能翻译 | 中泰双向、分页、回放、历史 | M3、泰文字形验证 | 双向测试集通过，关手机仍能翻译 |
| M5 日常工具 | 时区、天气、提醒、基础记忆 | M2、本地时钟 | 重启和断网提醒通过，删除记忆不会复活 |
| M6 完整角色生活 | 正式角色包、生成旅行、来源检索 | M3、M5 | 5 次旅行有差异，故事不进入真实事实 |
| M7 可长期使用 | HTTPS 部署、配网、OTA、备份、诊断 | M4–M6 | 7 天试用，升级与恢复演练通过 |
| M8 独立网络扩展 | 原生 BLE 配网、4G 调研样机 | M7、硬件选型 | 明确功耗、协议、地区网络、续航及成本 |

Wi-Fi 直连后端从 M2 就开始，不必等到 M8；M8 指蜂窝和更完整配网体验。正式角色素材可以与前期功能逐步替换，但不能把占位音色算作 Lunar 音色验收。

## 可直接派发的任务

- [ ] T00：按 M01 运行官方例程，产出 `docs/records/hardware.md`，区分电脑验证和实机结果。
- [ ] T01：按 M02 创建固件目录、输入事件层、页面路由和音频焦点仲裁；先用按键事件模拟测试。
- [ ] T02：按 M03 建立角色 manifest 校验、默认资源和切换回滚；加载占位预设。
- [ ] T03：按 M06 实现不依赖 AI 的生活时钟；断网重启验收。
- [ ] T04：按 M09、接口契约、数据模型建立后端、数据库迁移和 Mock provider。
- [ ] T05：按 M10 实现设备首页、角色和模型设置；显示 desired / applied 版本。
- [ ] T06：按 M04 打通录音上传、异步回复、取消和超时；再接真实服务。
- [ ] T07：按 M05 完成翻译与中泰字体链路；验证数字、否定和人名。
- [ ] T08：按 M07 实现天气与提醒，补云端存储但设备未确认的提示。
- [ ] T09：按 M08 实现分类记忆、编辑删除和双向同步。
- [ ] T10：按 M06 接生成小旅行；校验世界规则、去重与来源隔离。
- [ ] T11：按 M12 完成插件开关、配置校验和菜单更新。
- [ ] T12：按 M11 完成安全配对、部署、OTA 和恢复，补齐 M10 全部管理页面。
- [ ] T13：执行总验收及七天体验观察，产出版本发布记录。
- [ ] T14：另开蜂窝可行性阶段，测试后才决定追加模块和结构设计。

## 每个任务的交付格式

提交代码及版本；说明如何运行；列出测试步骤与结果；记录未完成项、所需实机操作和下一任务前置条件。至少一个成功路径和一个失败路径可复现。不能只有截图没有可构建工程。

新手一次推进一个任务。卡在素材时可用占位资源继续驱动和协议；卡在真实服务时用 Mock 继续页面；卡在硬件兼容时不能用模拟结果冒充硬件通过。

## 完整 v1.0 与首个演示的区别

M1 是离线演示，M3 是语音原型，M4 是带现实工具的原型。完成 M7 且所有发布门槛通过才可称本路线的 Wi-Fi v1.0；M8 的原生配网、蜂窝功能不得提前对外宣称支持。2–3 分钟首次配置是待测产品目标，不是已有结果。
