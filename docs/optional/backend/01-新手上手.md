# 新手上手：先做什么，怎么看懂

> 可选历史方案，非当前主线。请以 docs/README.md 和当前总架构为准；这里保留早期全功能后端设计，未实现。

## 你要做出的东西

设备自己显示角色和生活动画；按住按键讲话；设备通过 Wi-Fi 把语音发给后端；后端调用 AI，返回文字和声音。手机打开控制中心，修改角色、模型、记忆和设备设置。

第一轮只验证“按键能读到、屏幕能画、录音能播放”。没有角色素材、没有付费 AI 账号，也可以完成这一轮。

## 常见词

| 名词 | 白话解释 |
|---|---|
| 固件 firmware | 烧录进设备里运行的程序 |
| 编译 / 烧录 | 把代码变成设备能运行的文件 / 将文件写入设备 |
| 串口 COM | 电脑和设备通信、查看调试文字的通道 |
| 驱动 / HAL | 操作屏幕、按键、麦克风的底层代码 / 对它们的统一封装 |
| 后端 / API | 运行在电脑或服务器上的服务 / 调用这个服务的约定 |
| STT / LLM / TTS | 语音转文字 / 理解与生成文字的模型 / 文字转语音 |
| 状态机 | 规定当前处于什么状态、什么事件可以切换状态 |
| SQLite | 将结构化数据存进一个数据库文件的工具 |
| NVS / PSRAM | 设备断电仍保留的小配置存储 / 运行时内存，断电消失 |
| OTA | 通过网络更新固件 |
| Mock | 用可预测的假回复测试整条流程，不调用付费模型 |
| Git / commit | 保存代码历史的工具 / 一次可以回退的版本记录 |
| 幂等 | 同一操作重试多次，最终只生效一次 |

## 准备清单

- 已选的三件硬件，核对标签及版本；可传数据的 USB 线，稳定 5V 供电，2.4GHz Wi-Fi。
- Windows 电脑；项目路径固定为 `D:\m5Lunar`。
- microSD 作为角色资源和媒体缓存的建议扩展；容量、文件系统和读取速度先按官方示例验证。没有卡时用极小的内置占位资源。
- 后续准备角色参考图片、干净样音、语言偏好和模型服务账号。密钥仅配置到后端，不贴进源码。

## 工具安装顺序

1. 安装 Arduino IDE，按 [M5Stack 官方板管理教程](https://docs.m5stack.com/en/arduino/arduino_board) 安装板支持包。
2. 按 [StackChan 显示示例](https://docs.m5stack.com/en/arduino/stackchan/display) 选择开发板和库版本。该示例要求 M5CoreS3 板选项及相应最低库版本；这是示例起点，不是三件组合已通过认证。
3. 在 Windows 设备管理器中确认插拔设备对应的 COM 端口。仅从官方来源安装确实需要的驱动。
4. 后端阶段安装 Python 3.12 作为本项目建议基线；网页阶段安装 Node.js 22.12 或更高兼容版本。当前 Vite 的 Node 要求以 [官方指南](https://vite.dev/guide/) 为准。
5. 安装 Git，便于保存每个通过验收的小版本。暂不需要购买云服务器。

先用 Arduino IDE 跑通官方例程；正式固件再固定工具链和依赖版本。不要同时折腾多个烧录方案。把 IDE、板包、库版本和板选项写入硬件测试记录。

## 第一次操作

1. 核验装配与供电后，连接设备，记录出厂固件与恢复方式。
2. 打开官方显示示例，点“验证”，通过后选择正确 COM，点“上传”。
3. 检查屏幕是否出现示例图形；这只证明显示链路。
4. 单独跑 Gamepad3 示例，逐个按八键，检查串口文字随按下和松开变化。
5. 单独跑麦克风和扬声器例程，用小音量确认录制一句话后可回放。
6. 保存照片或日志、版本号和结果，再开始业务代码。

失败时一次只改一个因素。看不到 COM 先换数据线和接口；编译报错先保存第一条错误与依赖版本；按键读不到先核对底座与总线，不能乱试 GPIO。

## 未来代码实现后的运行方式

**以下是约定好的目标命令，不是现在能运行的项目。当前还没有 `backend`、`control-center` 源码或依赖文件。** 实现 M2 后由开发者落实这些命令并更新说明。

后端在 PowerShell 中运行：

```powershell
Set-Location 'D:\m5Lunar\backend'
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

预计浏览器访问 `http://127.0.0.1:8000/healthz` 得到状态 JSON，访问 `/docs` 查看接口。使用 `Mock` 模式先不放密钥。[FastAPI 官方入门](https://fastapi.tiangolo.com/tutorial/first-steps/)

网页控制中心另开 PowerShell：

```powershell
Set-Location 'D:\m5Lunar\control-center'
npm ci
npm run dev
```

`npm ci` 依赖实现阶段提交的锁文件。浏览器访问终端实际打印的地址。设备接入前按 M11 配置可验证证书的 HTTPS；设备的 `localhost` 指设备自身，不能填电脑的 `127.0.0.1`。本机纯 Mock 阶段的 HTTP 仅用于电脑调试。

## 你需要做的决定

现在只需记录硬件是否已到手、手机系统、默认角色素材是否齐全。模型供应商、原生 App 框架、蜂窝模块可以后续选；见 [待确认事项](07-待确认事项与资料来源.md)。

每完成阶段，可按这个格式请求下一步开发：“请实现路线中的 M1，只完成列出的交付和验收；报告哪些在电脑验证、哪些仍需实机验证。”
