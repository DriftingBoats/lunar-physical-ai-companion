# 数据模型与同步

> 可选历史方案，非当前主线。请以 docs/README.md 和当前总架构为准；这里保留早期全功能后端设计，未实现。

## 1. 谁保存什么

| 数据 | 主存储 | 设备本地 | 保留策略（建议默认） |
|---|---|---|---|
| 用户、设备绑定、模型密钥 | 后端 | 仅设备自身令牌 | 解绑撤销令牌，密钥不备份到设备 |
| 角色与配置 | 后端版本化记录 | 最近成功版本与待应用版本 | 不删除仍被历史引用的版本元信息 |
| 生活状态 | 设备 | 主副快照或带 CRC 日志 | 状态变更及每 5 分钟检查点 |
| 提醒 | 后端 + 本地操作队列 | 未完成及近期完成项 | 未确认上传前不淘汰 |
| 长期记忆、Profile | 后端 | 最近 100 条浏览缓存 | 用户删除优先于恢复和重试 |
| 翻译历史 | 后端或用户配置的短期存储 | 最近 20 条 | 默认 7 天，用户保存为记忆才长期留存 |
| 原始录音 | 后端临时目录与内存 | 本次录音缓存 | 任务结束即清理；异常兜底最长 24 小时 |
| TTS / 译文分页图片 | 私有媒体存储 | 按最近使用淘汰 | 默认 7 天；不能承诺过期后离线回放 |
| 天气 | 后端缓存 | 最近成功一次 | 30 分钟刷新，2 小时后标过期 |
| 调试日志 | 限量日志 | 固定大小环形缓冲 | 7 天；不含密钥、完整音频和默认全文对话 |

保留策略需要在控制中心可见。备份默认 30 天滚动保留，恢复后重新应用删除记录。上述数量不是硬件实测容量，超限必须有淘汰策略。

## 2. 核心表

所有可同步实体包含 `id, owner_id, revision, created_at, updated_at, deleted_at`；device 侧引用 companion_id。时间统一 UTC；revision 为单调递增整数，不能用设备时间判断最后写入。

| 表 | 专属字段 / 约束 |
|---|---|
| users | login_name UNIQUE、password_hash；不存明文密码 |
| companions | active_character_preset_id、active_character_version、timezone |
| devices | companion_id、hardware_id、token_hash、last_seen_at、applied_revision、capabilities |
| character_versions | preset_id + version UNIQUE、manifest、settings；发布后不可原地改写 |
| configurations | companion_id + revision UNIQUE、desired_snapshot |
| provider_profiles | capability、provider、model、endpoint、encrypted_secret_ref、timeout、budget |
| jobs | client_event_id、type、status、result、error、deadline_at；(owner_id,client_event_id) UNIQUE |
| events | event_id UNIQUE、device_id、type、occurred_at、received_at、payload、source_type |
| memories | companion_id、source_type、title、content、evidence_event_ids、character_preset_id、character_version、occurred_at、generated_at |
| profile_facts | key、value、evidence_ids、origin=user_reported/confirmed_interaction；不得来源于 fictional_trip |
| reminders | title、due_at、timezone、status、snoozed_until、applied_device_revision |
| trip_plans | plan_event_id UNIQUE、character_version、rule_version、status、depart_at、return_at、memory_id |
| assets | owner_id、sha256、type、bytes、private_path、expires_at、ref_count |
| sync_changes | server_sequence、entity、entity_id、operation、revision |
| deletion_ledger | entity、entity_id、deleted_revision、deleted_at；保存最小删除标识，不保留内容 |

SQLite 开启外键，数据库迁移有版本号；一次业务提交的实体、事件和 change 在同一事务里写入。向量索引是派生数据，首版可不用；未来加入时也不能成为唯一存储。

## 3. 记忆示例

```json
{
  "id":"mem_demo_01",
  "companion_id":"comp_demo_01",
  "revision":1,
  "source_type":"fictional_trip",
  "title":"便利店的小旅行故事",
  "content":"角色想象自己带回了一张饮料贴纸。",
  "evidence_event_ids":["evt_trip_demo_01"],
  "character_preset_id":"lunar",
  "character_version":1,
  "occurred_at":"2026-09-09T08:00:00Z",
  "generated_at":"2026-09-09T07:50:00Z",
  "context_sources":[{"kind":"weather","observed_at":"2026-09-09T07:30:00Z"}],
  "deleted_at":null
}
```

occurred_at 在故事里是叙事时间，不是现实证明。真实翻译只证明设备处理过翻译；用户位置需单独有用户自述或可靠事件，不能根据泰语猜城市。

## 4. 本地写入和恢复

- 小配置用 NVS；大媒体用 SD，业务状态不要每一帧写 Flash。
- 每个快照有 schema_version、revision、CRC；写临时记录，校验再替换；启动选最近一个有效版本。
- 待上传操作放 outbox，先落盘再改界面。未获 accepted 不删除；已接受的 event_id 不再次执行。
- SD 拔出后用内置资源继续 Home；保留在 NVS 中的关键提醒和令牌。历史媒体显示“暂时无法读取”。
- 磁盘满先清临时媒体，再清可重建缓存；不静默删除未完成提醒和 outbox。关键写入失败必须告诉用户未保存。

## 5. 冲突规则

配置由网页提交 desired，设备仅 ack；生效版本不倒退。用户事实和记忆文本冲突返回 409，让用户选择保留哪版。自动生成不能覆盖用户编辑。

提醒 completed/cancelled 为终态；相同或更旧 revision 的 snooze 不得复活终态。若用户要再次提醒，应新建记录。设备离线完成与云端取消相遇时保留终态和双方操作日志，不再次响铃。

删除优先：收到墓碑立即移除本地缓存、全文索引、摘要引用和可识别的派生媒体；索引完成前查询层已过滤删除 ID。下次摘要生成排除已删除事件。完全离线设备无法立刻清理，控制中心展示待同步删除状态。

## 6. 备份与换设备

导出 schema_version、companion 配置、角色版本引用、记忆、提醒及删除标识；默认不导出密码、provider secret、device token、原始录音。需要私有素材时在导出清单显式列出。

恢复先预览格式、重复 ID 和冲突，再事务化合并。服务器当前 deletion_ledger 优先于旧备份，禁止把已删除内容重新插入。新设备重新配对，获取新令牌；用户选择已有 companion 后恢复允许的数据。不能从旧设备备份复制密钥冒充新设备。

迁移验收：旧 schema 升新 schema；迁移失败保留备份并停止写入；回滚固件仍能读取上一个兼容配置。破坏性 schema 变更与 OTA 不在同一次无恢复点操作里执行。
